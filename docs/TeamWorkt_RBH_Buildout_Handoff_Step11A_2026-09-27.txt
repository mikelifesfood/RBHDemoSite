4. CORE WORKFLOW
======================================================================

Current six-step workflow:

Step 1 - Review
Step 2 - Investigation
Step 3 - Action Plan
Step 4 - Complete Action
Step 5 - Verification
Step 6 - Close

Ownership model:

Case Owner / Investigator
- Owns Steps 1-3.
- Can be Admin, Safety Manager, or Supervisor.
- Separate from the Corrective Action Owner.

Corrective Action Owner
- Owns Step 4.
- Can be a qualifying dashboard user.
- Existing database field: assigned_user_id.

Verification Owner
- Owns Step 5 when specifically assigned.
- Must be active Admin or Safety Manager.
- Optional.
- If no verifier is assigned, verification remains in the shared Admin/Safety Manager queue.

Closure
- Step 6 remains Admin/Safety Manager controlled.

Admins:
- Full workflow access.
- Admin tab access.
- Override verification assignment when needed.

Safety Managers:
- Full operational workflow access.
- No Admin tab.

Supervisors:
- Can work Steps 1-3 only when assigned as Investigator.
- Can work Step 4 only when assigned as Corrective Action Owner.
- Cannot verify Step 5.
- Cannot close Step 6.
- Cannot make regulatory screening decisions.

Read Only:
- View only.
- No operational workflow updates.

5. REGULATORY / INJURY SAFEGUARDS
======================================================================

Important design rule:
A Supervisor Investigator can work Step 1 on an injury report, but cannot complete Step 1 until an Admin or Safety Manager has completed the regulatory screening.

Supervisors do NOT gain Cal/OSHA screening authority.

Current regulatory design:
- Worksite jurisdiction matters, not employee residence or company HQ.
- Do not imply the app itself makes a final legal determination.
- Do not imply the app automatically files with OSHA / Cal/OSHA unless an actual regulator integration is later built.
- California language should use elapsed time and “immediately/as soon as practical,” not a false “8-hour countdown.”
- Regulatory warnings must remain visible even when optional workflow guidance is hidden.

Current persistent regulatory timer behavior:
- Injury report + screening Pending/Yes + awareness timestamp:
  elapsed time remains visible throughout the workflow.
- Pending = amber.
- Yes = red.
- 4+ hours = stronger warning.
- 8+ hours = prominent escalation.
- No screening result = no active timer.
- Review Screening from later steps temporarily opens Step 1.
- A Return to Current Step button appears so the user can return to the true workflow step.

7. CURRENT NOTIFICATION MODEL
======================================================================

Email and in-app notifications are separate layers.

EMAIL:
- Transactional.
- Delivered through Brevo.
- Deep-link back to authenticated report.
- Minimal report detail in email.
- Sensitive incident/report information remains behind login.

IN-APP:
- Persistent action queue.
- User-specific.
- Database-backed.
- Currently supports Viewed state.
- Bell count intentionally still represents unacknowledged actionable work.

Planned notification lifecycle:

Sent
-> Viewed
-> Acknowledged
-> Completed / Resolved

Important:
Opening a notification is NOT acknowledgment.
